# CoughScan

Нативное приложение SwiftUI: микрофон → секундные mono PCM WAV → multipart POST `/upload` → дневная/почасовая статистика. Минимальная версия сохранена: iOS 27.0. Существующие UserDefaults и формат очереди совместимы; существующая статистика не пересчитывается задним числом.

## Изменения для тестовой сборки 1.0 (2)

- Согласованы запись и закрытие WAV; последний фрагмент сохраняется при остановке. Ошибки записи видны на экране.
- Очередь восстанавливается после запуска, обрабатывается без задержки после успеха; сетевые ошибки повторяются с паузой до 60 секунд без удаления файлов.
- HTTP 2xx и обязательные поля ответа проверяются. Ошибочный JSON не сохраняется как отрицательный результат.
- События относятся ко времени записи; поддержан необязательный `cough_count`, сохранён fallback на один положительный фрагмент.
- Исправлены взвешенная вероятность, семь календарных дней, учёт времени без ответов сервера и переход через полночь.
- Очистка останавливает запись, отменяет запросы, удаляет локальные аудиофайлы, очередь, статистику и карточку пациента.
- CSV экранирует пользовательский текст, экспорт поддерживает popover iPad. Экран статистики обновляется при изменениях.
- Добавлены согласие на отправку аудио, декларация UserDefaults в PrivacyInfo.xcprivacy и базовая иконка. ATS-исключение ограничено существующим сервером.

## Серверный контракт

`CoughUploadURL` в Info.plist сохраняет текущий HTTP URL. Поля multipart: `audio`, `device_id` (старое значение `ios_<model>` сохранено). Ответ: `probability` (0...1), `cough_detected` (Bool), необязательные `status`, `message`, `cough_count`. Ответы status=error/failed/failure не принимаются. Результаты записываются локально только после успешной валидации. Для сетевых повторов серверу желательно поддерживать идемпотентность по имени файла: после потерянного ответа повторная доставка возможна.

## Проверки

Из этой папки:

```sh
swiftc -parse-as-library CoughScan/Models.swift CoughScan/CoughStorage.swift CoughScan/AudioChunkWriter.swift Tests/RegressionChecks.swift -o /tmp/coughscan-regression
/tmp/coughscan-regression
```

Проверки используют отдельный UserDefaults suite и временные файлы. Проверяют статистику, исходные даты, валидацию JSON, очистку, CSV и закрытие stereo → mono WAV.

## TestFlight и App Store

Без Xcode на своём компьютере: сборка и загрузка в TestFlight через GitHub Actions — см. [docs/testflight-github-actions.md](docs/testflight-github-actions.md).

1. В Xcode открыть CoughScan.xcodeproj, выбрать свой Team и уникальный Bundle ID при необходимости. Для следующей загрузки увеличить build number, если 2 уже использован.
2. Generic iOS Device → Product → Archive → Validate App → Distribute App → App Store Connect. Неподписанная локальная сборка не заменяет Validate App с учётной записью разработчика.
3. На iPhone проверить: разрешение/отказ микрофона, старт/стоп, 10–30 минут мониторинга, блокировку экрана, звонок, подключение/отключение Bluetooth, отсутствие сети и последующее восстановление, перезапуск с очередью, очистку во время отправки, смену дня и CSV на iPad. При изменении аудиомаршрута запись останавливается с сообщением; повторный старт ручной.
4. Заполнить App Privacy по реальной работе сервера. Клиент отправляет аудио и модель устройства; ФИО и заметки остаются локально, кроме пользовательского CSV-экспорта. Заявление Audio Data / App Functionality / not linked в manifest нужно сверить с серверным хранением, логами и идентификаторами.
5. До публичного релиза нужны действующие Privacy Policy URL, Support URL и доступная внутри приложения политика с оператором, контактом, сроками серверного хранения и способом удаления. Не утверждать, что локальная очистка удаляет серверные записи.
6. Настроить HTTPS на сервере, затем заменить CoughUploadURL и убрать HTTP-исключение. Сейчас HTTP сохранён для совместимости; соединение не зашифровано. HTTP HEAD вернул 308 с перенаправлением на HTTPS; первый HTTPS HEAD завершился таймаутом. Анализ аудио сервером не проверялся, аудио не отправлялось.
7. В Review Notes объяснить необходимость фоновой записи, явный запуск/остановку пользователем и индикатор мониторинга. Приложение не заявляет медицинскую диагностику; качество модели здесь не проверяется.

Остающиеся ограничения: UserDefaults хранит очередь и статистику целиком, при длительном офлайне WAV занимают диск; нет лимита длительности/объёма. Для нагрузочного тестирования контролировать свободное место. Изменение системного времени и аварийное завершение до очередного сохранения времени могут влиять на учёт последних секунд. Это тестовая стабилизация, а не подтверждение прохождения App Review.

Официальные требования: https://developer.apple.com/app-store/review/guidelines/ и https://developer.apple.com/app-store/app-privacy-details/ .
